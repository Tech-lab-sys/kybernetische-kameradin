## 2026-06-24 - Container Port Binding and n8n Execution Data
**Vulnerability:** The n8n docker container was exposing its port 5678 externally on all interfaces, and `EXECUTIONS_DATA_SAVE_ON_SUCCESS` was enabled. Both posed significant risks, especially since n8n handles sensitive user data and credentials, and the external access should exclusively be routed through the Cloudflare tunnel.
**Learning:** Default docker-compose configurations often map ports to all interfaces (`0.0.0.0`) instead of explicitly restricting to localhost (`127.0.0.1`), causing services to be unintentionally accessible externally. Additionally, verbose default data saving policies in automation platforms like n8n can inadvertently record and save secrets, PII, and sensitive logic directly into the database on successful executions.
**Prevention:** Always restrict container port mappings to localhost when an external proxy or tunnel is used. Furthermore, disable execution data retention for successful runs (`EXECUTIONS_DATA_SAVE_ON_SUCCESS: none`) to enforce a least-privilege approach regarding sensitive data storage.
