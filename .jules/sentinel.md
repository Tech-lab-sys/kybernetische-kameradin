## 2024-06-15 - Unbound Container Port & Excessive Data Retention
**Vulnerability:** The n8n container was binding its port (5678:5678) directly to all interfaces instead of just localhost, bypassing the intended Cloudflare Tunnel security and exposing the n8n application directly to the internet. Additionally, successful workflow executions were being saved (`EXECUTIONS_DATA_SAVE_ON_SUCCESS: all`), risking the retention and potential exposure of sensitive PII or secrets processed within n8n.
**Learning:** Default Docker port bindings in `docker-compose.yml` bind to `0.0.0.0` unless an IP is specified. When using a local reverse proxy or tunnel (like Cloudflared), it's critical to bind container ports exclusively to `127.0.0.1`. Furthermore, n8n saves execution data by default; for workflows processing sensitive data, success execution logging must be disabled to prevent data leakage.
**Prevention:** Always explicitly bind to `127.0.0.1` (`"127.0.0.1:PORT:PORT"`) for any container not intended to receive direct external traffic. Audit logging/execution configurations in services that process sensitive information to ensure principle of least privilege in data retention (`EXECUTIONS_DATA_SAVE_ON_SUCCESS: none`).
