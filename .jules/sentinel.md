## 2026-06-18 - Unbound Container Port Exposure
**Vulnerability:** The n8n container port in `docker-compose.yml` was bound to all interfaces (`"5678:5678"`) instead of being restricted to localhost. This allowed direct external access to the service, bypassing intended reverse proxies or tunnels. Additionally, execution data saving for successful runs was enabled (`EXECUTIONS_DATA_SAVE_ON_SUCCESS: all`), risking exposure of sensitive PII and secrets on disk, contrary to security best practices.
**Learning:** Container ports mapped without an explicit host IP default to `0.0.0.0`, exposing the service publicly. Since the project uses a Cloudflare tunnel for external access, the service only needs to be accessible locally. Furthermore, saving execution data for successful runs by default increases the attack surface for local data breaches.
**Prevention:** Always explicitly bind container ports to `127.0.0.1` (`"127.0.0.1:5678:5678"`) when the service is intended to be accessed only locally or via a tunnel/reverse proxy running on the same host. Ensure `EXECUTIONS_DATA_SAVE_ON_SUCCESS` is set to `none` to minimize sensitive data storage.
